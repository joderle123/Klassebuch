Anleitung

App hinzufügen

Jede App bleibt eine eigene Datei — der Hub zeigt sie nur an. An der App selbst musst du nichts ändern, und ihre Daten bleiben dieselben, ob du sie im Hub oder direkt öffnest.

1
Datei ablegenDie App-Datei in den Ordner apps/ neben hub.html legen.
2
Eintragenhub-apps.js öffnen, den Vorlage-Block kopieren und Name, Symbol, Farbe, Bereich und Pfad anpassen.
3
Neu ladenhub.html mit Strg + F5 neu laden. Die App erscheint als Karte und im Menü.

Die Vorlage

So sieht ein Eintrag in hub-apps.js aus. Kopiere ihn innerhalb der eckigen Klammern [ … ] unter die bestehenden Apps:

{
  id: 'meine-app',
  name: 'Meine App',
  beschreibung: 'Wofür die App gut ist — ein Satz.',
  symbol: 'app',          // buch · test · ziel · werkzeug · wissen · web · app
  farbe: '#8A5A2B',
  bereich: 'Team & Organisation',
  datei: 'apps/meine-app.html'
},   ← dieses Komma nicht vergessen
Häufigster Fehler: das Komma nach } oder ein fehlendes Anführungszeichen. Der Hub merkt das und zeigt dir oben in der Übersicht eine Warnung, statt einfach leer zu bleiben.

Welche Art von App hast du?

A · Eine einzelne HTML-Datei funktioniert sofort

Wie der ELDiB-Generator oder das Screening: eine .html-Datei, die man per Doppelklick öffnet. Einfach ablegen und mit datei: 'apps/name.html' eintragen — fertig.

Arbeitet die App mit Dateien oder Ordnern — etwa einer Team-Datei auf O:\ oder Sicherungen, wie Klassenbuch und Toolbox —, ergänze dateizugriff: true. Dann öffnet sie in einem eigenen Tab (Erklärung unten bei „Wenn etwas nicht klappt").

B · Eine React- oder Vite-App einmal umbauen

Ein Projekt mit package.json, das mit npm run build gebaut wird. Ein normaler Build erzeugt einen Ordner mit ausgelagerten Programmteilen — und die blockiert Edge bei lokalen Dateien, die App bliebe weiß. Die Lösung ist, sie als eine einzige Datei zu bauen:

  1. Im App-Ordner einmal ausführen: npm install -D vite-plugin-singlefile
  2. In vite.config.ts das Plugin ergänzen (siehe unten).
  3. npm run build ausführen.
  4. Die Datei dist/index.html umbenennen, in den Ordner apps/ legen und wie bei Weg A eintragen.
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import { viteSingleFile } from 'vite-plugin-singlefile'   // neu

export default defineConfig({
  plugins: [react(), viteSingleFile()],   // viteSingleFile() neu
  base: './',
})
Die Toolbox (ISA-App) wird bereits genau so gebaut — sie ist ein gutes Vorbild.

C · Eine Webseite oder ein Online-Dienst öffnet im neuen Tab

Zum Beispiel ein Schulportal, Teams oder SharePoint. Statt datei trägst du link: 'https://…' ein. Solche Seiten öffnen sich in einem neuen Tab, weil die meisten Webseiten das Einbetten verbieten.

Eine App ohne datei und ohne link erscheint als geplant — praktisch, um schon einen Platz zu reservieren.

Konten & Teams

Jede Person erstellt beim ersten Mal ein eigenes Konto mit Name, Team und Passwort. Danach reicht das Passwort. Das Konto liegt als Datei im Hub-Ordner, im Unterordner konten/. Das Passwort selbst wird nirgends gespeichert — nur ein damit verschlüsselter Schlüssel.

Das Team bestimmt, welche Apps man sieht:

Welche Teams eine App sehen, steht in hub-apps.js im Feld teams. Ein neues Team trägst du dort oben bei CDSE_TEAMS ein. Das eigene Team ändert man im Hub unten links über das Menü ⋮ → Team ändern.

Ehrlich gesagt: Die Team-Wahl steuert, was man im Hub sieht. Eine echte Sperre ist das nicht — wer den Dateipfad kennt, kann eine App auch direkt öffnen. Soll das Screening wirklich nur für das Diagnostique-Team zugänglich sein, setzt die IT die Ordnerrechte: Nur diese Gruppe darf apps/screening.html lesen.

Deine Daten

Während du angemeldet bist, liegen die Daten der Apps wie gewohnt im Browser dieses PCs — die Apps merken keinen Unterschied. Der Hub sichert sie jede Minute verschlüsselt im Hub-Ordner (daten/) und entfernt sie beim Abmelden vom PC. Meldest du dich an einem anderen PC an, lädt er sie dort. Die Stände der letzten 14 Tage bleiben erhalten: Konto-Menü → Frühere Stände.

Öffne die Apps deshalb immer über den Hub. Direkt geöffnet, sieht eine App nach dem Abmelden leer aus — die Daten sind dann sicher im Hub-Ordner, nur eben nicht auf dem PC.

Das Klassenbuch im Team

Das Klassenbuch teilt ein Team über eine gemeinsame Team-Datei. Der Hub legt dafür pro Team einen Ordner an: teams/<Team>/. Eine Person erstellt dort im Klassenbuch die Datei klassebuch-team.json, alle anderen öffnen dieselbe Datei. Welche Datei du gewählt hast, merkt sich der Hub für dein Konto.

Passwort vergessen? Beim Erstellen bekommt jede Person einen Wiederherstellungs-Code. Nur damit lässt sich ein neues Passwort setzen. Ohne Code kann niemand helfen — auch die IT nicht. Genau das schützt die Daten.

Wenn etwas nicht klappt

Die Übersicht zeigt „App-Verzeichnis fehlerhaft"

In hub-apps.js ist ein Tippfehler — fast immer ein fehlendes Komma nach } oder ein fehlendes Anführungszeichen '. Die genaue Stelle zeigt dir Edge: F12 drücken, Reiter Konsole. Dort steht rot etwa hub-apps.js:63 — der Fehler steckt in dieser Zeile oder direkt davor.

Die App bleibt weiß

Fast immer eine React/Vite-App mit normalem Build. Baue sie als Einzeldatei (Weg B).

Edge zeigt „Datei nicht gefunden"

Der Pfad in datei stimmt nicht. Prüfe Ordnername, Dateiname und Groß-/Kleinschreibung. Der Pfad gilt von hub.html aus.

Wo liegen meine Daten?

Während du angemeldet bist, im Browser dieses PCs — genau wie früher. Zusätzlich sichert der Hub sie jede Minute verschlüsselt in daten/<dein Konto>/ im Hub-Ordner. Beim Abmelden entfernt er sie vom PC. Lesen kann sie nur, wer dein Passwort oder deinen Wiederherstellungs-Code kennt.

Beim ersten Anmelden fragt der Hub „Gehören sie dir?“

Auf dem PC lagen schon App-Daten aus der Zeit vor den Konten. Sind es deine, übernimmt der Hub sie in dein Konto. Sonst legt er sie auf diesem PC beiseite; wem sie gehören, holt sie sich später an diesem PC über Konto-Menü → Frühere Stände.

Ich habe an zwei PCs gleichzeitig gearbeitet

Dann gewinnt nichts still: Der Hub lädt den neueren Stand und legt die Änderungen des anderen PCs als Kopie ab (Konto-Menü → Frühere Stände). Am einfachsten: am alten PC abmelden, bevor du woanders weitermachst.

Warum öffnen Klassenbuch und Toolbox in einem eigenen Tab?

Beide arbeiten mit Dateien und Ordnern: das Klassenbuch mit der Team-Datei und den Sicherungen auf O:\, die Toolbox mit der Team-Ablage. Edge erlaubt diese Auswahl bei lokalen Dateien nur in einem eigenen Tab, nicht in einer eingebetteten Seite. Deshalb öffnet der Hub solche Apps in ihrem eigenen Tab. Ist der Tab schon offen, holt der Hub ihn nur nach vorne — ohne Neuladen.

Wie kommt die neueste Version einer App in den Hub?

Jede App hat in hub-apps.js eine quelle. Das Skript update-apps.cjs holt von dort die neueste Fassung und aktualisiert den „Stand" auf der Karte. Liegt irgendwo eine noch neuere Fassung derselben App, meldet es das, statt sie ungeprüft zu übernehmen. Am einfachsten bittest du Claude: „Aktualisiere die Apps im Hub."

Der Hub fragt nach dem Hub-Ordner

Beim ersten Mal wählst du den Ordner, in dem hub.html liegt (z. B. O:\CDSE-Hub). Danach fragt Edge meist nur noch einmal pro Sitzung: Zugriff erlauben. Ohne diesen Zugriff kann der Hub die Konten nicht lesen.

Der Hub ist gesperrt

Nach 60 Minuten ohne Aktivität sperrt sich der Hub; dein Passwort entsperrt ihn wieder. Die Zeit steht in hub-apps.js bei sperreNachMinuten. Gehst du vom Platz weg: Windows-Taste + L sperrt den ganzen PC.

Ein Konto löschen

Im Ordner konten/ liegt pro Person eine Datei, z. B. anna-muster-k3f.json, und in daten/ ein gleichnamiger Ordner mit den verschlüsselten Daten. Wer beides löscht, löscht das Konto samt Daten.

Eine Webseite lässt sich nicht einbetten

Viele Webseiten verbieten das. Trag sie mit link statt datei ein — dann öffnet sie sich in einem neuen Tab.

So legst du alles ab

Ein eigener Ordner, z. B. O:\CDSE-Hub\

  hub.html              ← diese Seite: öffnen und als Favorit speichern
  hub-apps.js           ← das App-Verzeichnis (mit den Teams)
  konten/               ← ein Konto pro Person (legt der Hub selbst an)
  daten/                ← die verschlüsselten Daten jeder Person, mit Ständen der letzten 14 Tage
  teams/                ← pro Team ein Ordner für die gemeinsame Klassenbuch-Datei
  apps/
    klassenbuch.html
    journal.html
    screening.html
    eldib-generator.html
    toolbox.html
    versionen.js        ← Stand jeder App (wird automatisch erzeugt)
    kb-screening-texte.js ← Texte für die Übernahme alter Klassenbuch-Screenings
